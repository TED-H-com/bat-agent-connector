# v1.3 E03 Work follow-up (second input)

This note records the Work-lane slice that queues one next instruction for a
connector-managed work item. It follows the reviewed loop spec's second-input
rules and the operation contract at `23e17e76`. It does not use the older
`0ab073fc` field names.

## Where it is mounted

The section is `[data-work-section="next-turn"]` inside the existing Work lane
of a linked session (`viewSession`). Work, Lineage, and Live hide that lane.
They do not rebuild the textarea, the legacy `#workspace-message-input`, or
`[data-workspace-result]`.

The earlier loop note placed this section in the kanban inspector. This slice
does not mount there. Kanban cards do not show it.

The legacy session composer stays. It still sends `{host, session_id}` with
`queue: true` when the person uses it. The new section never falls back to
that target.

## When it is shown

All of these are required:

- `features.pm_workspaces.work_follow_up` is `{version: 1, available: true}`.
- The workspace id is the one the shell already selected (`ws_` + 32 hex).
- The work item id is `work_item.work_item_id` on the linked item (`wi_` + 20 hex).
- The browser build is in use. The desktop shell does not offer the section
  until its typed routes can read the input list and the attempt result.
- The attempt result is `pm-work-attempt-result/v1` for that same work item,
  and `next_allowed_actions` contains `session.send` whose target is exactly
  `{workspace_id, work_item_id}`, with `after_current` allowed.
- The session observation is `provenance: connector_managed` and
  `api_access: managed`, and the principal has `operate` plus `session.send`.

Missing capability, `available: false`, a manual or unknown session, a Codex
block (`codex_uncorrelated_turn_boundary`), or `not_controller` leaves the
section without a send, cancel, or resume control. A result `403` keeps the
list and shows the shared read-only pill. A list `403`/`404`/`410`, or a
result `404`/`410`, removes the list, the receipt text, and the controls
together. A later `200` for that same read does not put them back.

While the result read is unfinished, there is no send button.

## What is sent

`POST /api/v1/operations` with action `session.send`.

- `target` is only `workspace_id` and `work_item_id`.
- `params` is trimmed `text` and `schedule: "after_current"`. `now` is not
  offered, even when the result also lists it.
- `preconditions` is `{expected_attempt_id}` when the list reported a real
  `att_` + 32 hex id, otherwise `{}`.
- Empty text is not posted. Text longer than 20,000 characters is not posted.
- The idempotency key is the durable-form key. A lost acknowledgement retries
  that same key. `PM_WORK_ATTEMPT_CHANGED` and `INVALID_PRECONDITIONS` drop the
  key and keep the typed text. An admission refusal uses New request.

Busy means the server queue (`after_current`), not a local queue and not
`schedule: now`.

## What counts as accepted

Only `operation.input_receipt` on the operation response. `result.input_receipt`
is ignored. The list row's `labels.state` and `labels.detail` for the active
locale are shown as the service wrote them. A missing locale string is
"Unknown" / "未知", not English copied into Traditional Chinese. Queued is not
called sent.

After that id, the field clears and can take another instruction. The first
receipt remains. Two identical sentences are two keys and two operation ids.
Cancel and resume post `{}` to the operation endpoint named by the receipt,
and only when that action's `operation_id` is this receipt, the actor matches,
and cancel is still `cancellable`. A blocked later row links to
`blocked_by_operation_id` and does not resume that later row. Edit and retry
copy `params.text` into the field and do not submit it. They do not read the
operation back, and they do not substitute `text_excerpt`.

The list is `GET .../work/{work_item_id}/inputs`. `has_more` says there are
more steps and does not invent a total. `visibility_filtered` says some steps
are hidden and does not show zero. There is no second event reader, poll loop,
or draft store. The existing durable form and the session's event refresh are
reused.
