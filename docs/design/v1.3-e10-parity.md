## 1. 範圍

### 1.1 R1 要 E10 補上的

計畫 `:542` 的 R1 是 E01–E05 加上 E10 的最小對等。`:108` 把 MCP 定成產品的 agent 入口。`:422` 要求回應帶上 Work、Attempt、Operation、目前狀態、下一個允許動作、打得開的 Dashboard 深層連結，以及資料完整度。不可以只回成功。`:631` 要求 agent 不點 UI、不共用管理員 token、不偽裝成另一個 controller。

A15（`:572`）是外部 agent 不點 UI 就開始自己的工作，Dashboard 看到同一筆 Work 與 Attempt。A16（`:573`）是同一授權意圖，兩種入口的規則、狀態與 Result 相同，操作來源仍分得出來。

今天這條路的寫入已經進同一個 `OperationService`。差的是回應沒有那組共用欄位、深層連結怎麼組成絕對 URL 沒有寫下來，以及 canonical skill 沒有把整條迴圈教完。E10 只補這三件事，再加上實作階段的對等測試。

### 3.1 計畫要的，和今天有的

Hash 只有這四個，定義在 `src/bat_agent_connector/pm_attempt_result_reads.py:173`：

`blocked_actions.reason` 今天用的字串是 `not_controller`、`missing_scope`、`not_writer_member`、`WAIT_ORIGINAL_OPERATION_RECONCILE`（`src/bat_agent_connector/pm_attempt_result_reads.py:937-953`）。`kind` 只有 `operation_endpoint` 與 `action`。E04 §5.2 寫了哪些動作在哪種執行狀態出現。E10 不重寫那張表。

Operation 讀寫還沒有這些欄位。`OperationService.get` 回的是 decode 後的列加 steps（`src/bat_agent_connector/operations.py:359`）。公開列沒有 `loop`、`attempt_id`、`links` 或 `completeness`。

### 3.3 拒絕

HTTP create_operation 對 pm.*、setup.host、setup.repository、setup.verification、work.start 會把 admission 失敗包成 error，並在沒有舊 key 時加上 admission_refused，見 src/bat_agent_connector/api_v1.py:1494-1495。RPC 沒有這層。OperationError 在 daemon 出口被收成 400，碼放在頂層 error。見 src/bat_agent_connector/task_daemon.py:949。

## 6. 處處成立的規則

MCP 與 HTTP 使用同一份已註冊動作、同一份 scope、同一套 controller 檢查，以及同一把 idempotency key。`operation_submit` 的 `entry` 是 `mcp`（`src/bat_agent_connector/mcp_server.py:393` 的 `principal_daemon`）。來源因此分得出來，規則不分叉。

Principal-only 的說明在 `src/bat_agent_connector/mcp_server.py:1797`。舊的 Fleet 寫入工具在 `:1513` 被拿掉。`operation_submit` 仍在。迴圈不使用共用的 admin token，也不借用另一個 controller 的 session。`principal_daemon` 要求 `confirm=true` 與呼叫端自己的 token（`src/bat_agent_connector/mcp_server.py:386-393`）。

Manual、foreign、unknown session 維持唯讀。不從 cwd、標題或路徑推測擁有權。要接別人的成果，開自己的工作，不往那條 session 送 `session.send`。

不確定的結果不重送 start，也不清 lock。恢復用原 operation id 與原 key。`operation_cancel` 與 `operation_resume` 維持既有工具（`src/bat_agent_connector/mcp_server.py:109` 的 `OPERATION_TOOLS`）。
