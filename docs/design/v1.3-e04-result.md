## 1. Result 信封契約（Envelope：`pm-work-attempt-result/v1`）

每個由 `work.start` 建立之 `attempt_id`（`att_<32hex>`）對應單一標準化 Result 信封回應（回傳最新一輪完整信封，並附該 Attempt 之回合回執列表 `results`）。所有欄位皆標明程式碼中實際存在之來源與 `path:line`，且遵守三項不變量：
1. **狀態分離**：模型自述（`self_reported`）、驗證（`verification`）、需求驗收（`acceptance`）、品質審閱（`review_decision`）、合併（`merge`）與部署（`deployment`）分屬獨立欄位；助手文字宣稱「已完成」或 `turn_done == True` 永遠只記為 `self_reported`，絕不等於驗證通過或需求驗收（計畫 §10.2）。
2. **未知誠實揭露**：無證據或來源未提供之指標一律維持 `"unknown"`，絕不填 `0`、`false` 或空陣列偽裝為零值或乾淨狀態（Hard Rule 6、計畫 §10.2）。
3. **用量不換算金額、不混用操作時間**：僅回傳來源原生提供之 token 與回合數；BAT 未提供之欄位（含單回合耗時 `duration_seconds`）維持 `"unknown"`，且禁止出現 `cost_usd`（計畫 §10.2）。

### 1.1 信封頂層結構與九大區塊來源對照表

## 2. 儲存與單一系統收集器決策（Storage & Single Server-Side Collector）

### 2.1 為何需要 E00 §4.2 `session_results` 表

1. **`sessions_observed` 為覆寫式快取**：`sessions_observed`（`inventory.py:197-205`）以 `ON CONFLICT(host, session_id) DO UPDATE` 覆寫單行，不保留歷史回合位置、助手摘要或當下 `HEAD` commit 與變更統計。
2. **`registry.get_turn` 為揮發性記憶體狀態**：`registry.py:322-366` 於 Connector 重啟後消失。
3. **無讀取者時亦須固定成果（計畫 §13「UI 關閉／斷線」）**：即使沒有任何瀏覽器或 MCP 客戶端呼叫讀取 API，回合結束時中心服務仍必須固定該輪 Result 並留存可引用之 `result_id`。

### 2.2 讀取絕不寫入、僅於回合邊界固定回執（Turn-Boundary-Only Collector：`actor="connector"`）

- **鐵則 1（Reads Never Write & `/result` Makes Zero BAT Calls）**：所有讀取端點（`/result`、`/changes`、`/diff` 與對應 RPC／MCP tools）為**純讀取（0 資料庫寫入、0 `api_events` 發出）**。`/result` 為有界投影，亦為 **0 次 BAT IPC 呼叫**（絕不呼叫 `SessionObservation.request` 或 `service.session_read`）。固定回執僅由單一服務端收集器（`AttemptResultCollector`，掛載於 `TaskDaemon.result_collector` 與 `ops.context["attempt_result_collector"]`）以系統身分 `actor="connector"` 寫入，絕不將回執歸因於碰巧發起讀取之使用者或 agent。
- **收集器檢查狀態（`AttemptResultCollector.last_check`）**：收集器於記憶體維護 `last_check: dict[attempt_id, {"checked_at": float, "outcome": str}]`，每次檢查設定 `'recorded' | 'unchanged' | 'mid_turn' | 'no_boundary' | 'turn_marker_not_visible' | 'registry_mismatch' | 'bat_error'` 七種結果之一；`/result` 投影為 `collection: {"status": "checked", "checked_at", "outcome"}`（重啟後或首次收集前為 `{"status": "not_checked_since_start"}`）。若檢查結果為 `turn_marker_not_visible`，讀取端無須即時讀取即可於 `completeness.reasons` 加入 `"turn_marker_not_visible"`。
- **鐵則 2（Receipts Only at Turn Boundaries，絕不於回合中途寫入）**：
  - **收集條件**：收集器**僅在 session 非串流中（`streaming is False`）、首句使用者 echo 可見（`turn_attribution == "correlated"`），且滿足下列任一終止邊界條件時**才寫入 `session_results`：
    1. 回合已完成且無待答問題／權限（`turn_done is True` 且 `pending is None`）；
    2. 程序已結束且 `session_read` 仍可成功讀取（`runtime_status in {"exited", "stopped"}` 或 `sessions_observed.gone_at is not None`）；
    3. 回合以錯誤結束（已開啟之 client `recent_events` 收到該 session 之 `channel == "agent:error"`）。
  - **為何禁止 Mid-Turn 快照**：若在助手訊息仍在增長時對同一 `(turn_marker, last_message_id)` 寫入中途快照，待該回合真正完成時同一 `last_message_id` 之訊息內容已改變，會算出不同 `digest` 而誤觸發假性 `source_digest_conflict`。
- **觸發訊號（`Inventory.after_refresh`，不建立新 BAT 連線或訂閱）**：
  - **為何不依賴常駐事件環**：`Inventory._refresh_scheduled` 於每次刷新後即關閉 client（`inventory.py:338-339`），且 ops fleet 會回收閒置超過 120s 之 client（`fleet.py:64-70`），故 `BatClient.recent_events` 僅保有連線期間碰巧收到之事件。
  - **Inventory 刷新後掛鉤（`Inventory.after_refresh`）**：於 `Inventory` 註冊非同步 hooks `(host, result) -> None`；`_refresh_scheduled` 在 `refresh_host` 完成且排定下次刷新時間後、**關閉 client 之前**依序呼叫各 hook（當 `refresh_host` 回報主機不可達時略過）。每筆 hook 設總時間預算 `COLLECT_PASS_BUDGET_S = 40.0s`，並攔截及記錄例外，確保失敗之 hook 絕不影響 inventory 自身之結果、排程或指數退避。
  - **輔助邊界證據**：收集器直接重用該已開啟之唯讀 socket（`checkpoints._read_fleet(ops)`；若無 inventory 自行建立唯讀 `Fleet` 時由 `AttemptResultCollector.close()` 於 daemon 關閉時釋放），可順帶讀取 `recent_events` 中該 session 之 `agent:error` 作為額外邊界證據，但絕不主動開啟新連線、新增訂閱或輪詢事件。
- **收集範圍、併發邊界與退避（Scope, Bounds & Backoff）**：
  - 僅限 `handoff` 子操作為 `succeeded`、子操作結果具備 `host`、`session_id`、`worktree_path` 與 `message_id`，且 `registry.get(host, session_id)` 之 `start_operation_id` 等於該 `handoff` 子操作 ID 之受管 Attempt。Manual、foreign、unknown 與 uncertain sessions 絕不讀取。
  - 每個 `host` 同一時間最多執行 **1 個**收集工作（per-host single-flight `asyncio.Lock` 並與該主機 refresh 序列化），每次 pass 每主機最多檢查 `COLLECT_MAX_PER_PASS = 8` 個最久未檢查之候選 Attempt，總預算 `COLLECT_PASS_BUDGET_S = 40.0s`，遵守 `channels.py:130-148` 之通道逾時。
  - 記憶體 Memo 以 Attempt 為鍵：當已有回執且 `sessions_observed` 之 `(digest, sort_key, gone_at)` 自上次檢查後未變動時直接略過，但至少每 `MEMO_RECHECK_S = 900.0s` 重新檢查一次；若最新回執已涵蓋相同 `source_position` 與 `digest` 亦不重複寫入。
  - 遭遇 `BatError` 或 `ConnectionLost` 時不為該 Attempt 寫入任何紀錄，留待後續 pass 重試並由 `Inventory` 自身退避治理主機；Connector 重啟後記憶體 Memo 為空，自動於每 pass 上限內對所有候選 Attempt 執行一次重啟補收（restart backfill）。

### 2.3 冪等 Schema DDL、本輪專屬雜湊與唯一性（對齊 E00 §4.2）

遵循 `docs/design/v1.3-e00-baseline.md:211` 之欄位（保留 `operation_id` 指向 `execution_operation_id` 以直接支援 `pm_source_lineage` 撤回檢核）與五鍵唯一性，不分配 `user_version`、無 Data Step：

```sql
CREATE TABLE IF NOT EXISTS session_results (
    sequence INTEGER PRIMARY KEY AUTOINCREMENT,
    result_id TEXT NOT NULL UNIQUE,
    workspace_id TEXT NOT NULL,
    attempt_id TEXT,
    source_key TEXT NOT NULL,
    source_generation TEXT NOT NULL,
    source_position TEXT NOT NULL,
    digest TEXT NOT NULL,
    document TEXT NOT NULL,
    observed_at REAL NOT NULL,
    collected_at REAL NOT NULL,
    operation_id TEXT NOT NULL,
    UNIQUE(workspace_id, source_key, source_generation, source_position, digest)
);
CREATE INDEX IF NOT EXISTS session_results_by_attempt
    ON session_results(workspace_id, attempt_id, sequence DESC);
CREATE INDEX IF NOT EXISTS session_results_by_position
    ON session_results(workspace_id, source_key, source_generation, source_position, sequence ASC);

CREATE TRIGGER IF NOT EXISTS session_results_no_update
BEFORE UPDATE ON session_results BEGIN
    SELECT RAISE(ABORT, 'session_results is append-only');
END;
CREATE TRIGGER IF NOT EXISTS session_results_no_delete
BEFORE DELETE ON session_results BEGIN
    SELECT RAISE(ABORT, 'session_results is append-only');
END;
```

- **`source_position` 與 `digest` 僅涵蓋本輪自身項目（排除 `turn_done`、Live/Archive 切分與 Worktree）**：
  - `source_position` 欄位固定為正規化 JSON 字串：`json.dumps({"last_message_id": last_message_id, "turn_marker": turn_marker}, sort_keys=True, separators=(",", ":"))`。
  - `digest` 僅對**本輪自 `turn_marker` 起至 `last_message_id` 為止之完整回合切片（`_turn_slice`）**計算 SHA-256（而非分頁或長度截斷後之 `messages`）。為取得完整回合切片，`service.session_read` 支援 keyword-only `turn_slice: bool = False`（比照 `index_reading`／`_reading_index` 模式）：當 `turn_slice=True` 時，於分頁前對 `selected` 計算 `_turn_slice = {"items": [summarize_message(m, include_tools=True, max_chars=DIGEST_TEXT_MAX_CHARS) ...], "complete": bool, "reason": str | None}`（保留最新 `TURN_SLICE_MAX_ITEMS = 2000` 筆，超限裁切時標記 `complete: False, reason: "turn_slice_bounded"`），由呼叫端 pop 出 `_turn_slice`；當 `turn_slice=False` 時既有輸出位元組完全不變。
  - **明確排除變動欄位**：`summarize_message` 回傳 `id, ts, role, text` 與選填之 `tool, status, completed_at, duration_ms, model, agent, denied, deferred`（無 `tool_calls` 或 `tool_results`）。由於 `ts` 與 `completed_at` 為本機時區字串（`iso_local`），且 `status` 等狀態與 metadata 可能事後回填，故 `turn_items` 僅由 `summarize_message(m, include_tools=True, max_chars=DIGEST_TEXT_MAX_CHARS)`（`DIGEST_TEXT_MAX_CHARS = 20_000`）保留 `id, role, tool, text` 四欄，並排除 `turn_done`、live/archive 切分指標、worktree `head_sha`、`uncommitted`、changeset、驗證與交付狀態。任何對此規則、`summarize_message` 或 `clip` 之修改皆須遞增 `DECODER_VERSION`。
  - **精確正規化演算法（Canonical Form）**：兩收集器必產生完全相同之 UTF-8 bytes：
    ```python
    canonical_digest_input = {
        "decoder_version": "bat_ipc_session_v1",
        "last_message_id": str(last_message_id or ""),
        "source_generation": str(source_generation),
        "source_key": str(source_key),
        "turn_items": [
            {
                "id": str(item.get("id") or ""),
                "role": str(item.get("role") or ""),
                "tool": str(item.get("tool") or ""),
                "text": str(item.get("text") or ""),
            }
            for item in turn_items  # chronological slice from turn_marker (exclusive) through last_message_id (inclusive)
        ],
        "turn_marker": str(turn_marker or ""),
    }
    digest = "sha256:" + hashlib.sha256(
        json.dumps(canonical_digest_input, sort_keys=True, ensure_ascii=False, separators=(",", ":"), allow_nan=False).encode("utf-8")
    ).hexdigest()
    ```
- **同位置異雜湊與並發寫入規則**：相同 `(workspace_id, source_key, source_generation, source_position, digest)` 以 `INSERT OR IGNORE` 冪等保留單一列；若成功插入新列則發出 `work.attempt.result_recorded`（`actor="connector"`）。若同一 `(workspace_id, source_key, source_generation, source_position)` 已存在**相同 `decoder_version` 且不同 `digest`** 之紀錄，新列一併存入表中（絕不更新或刪除舊列），並額外發出 `work.attempt.result_conflict` 事件（`actor="connector"`）；不同 `decoder_version` 間不視為衝突。讀取端偵測同一位置與相同 `decoder_version` 存在 `>1` 個 `digest` 時標記 `completeness.status = "partial"` 且原因加入 `"source_digest_conflict"`。

### 2.4 `session_results.document` 有界 Schema、版本與 256 KiB 上限（E00 §4.2）

- **Schema 版本與大小上限**：`document` 頂層固定帶 `"schema_version": "session-result-doc/v1"`，序列化後 UTF-8 位元組上限為 `MAX_RESULT_DOCUMENT_BYTES = 262_144`（**256 KiB**）。
- **僅存 ID、公開摘要與有界預覽（不存 Raw Blobs）**：
  - `turn_item_ids: list[str]`（本輪訊息 ID 清單，上限 200 個）；
  - `latest_assistant_summary`（來自 `lifecycle._final_output`，固定帶 `claim_status: "self_reported"`，`text` 裁切上限 4,000 字元）；
  - `messages_preview`（本輪最末最多 20 則訊息，每則 `text` 裁切上限 1,000 字元）；
  - `tool_activity`（本輪最末最多 50 筆工具摘要，每筆 `summary` 裁切上限 500 字元）；
  - `changes_summary`（最多 `BRANCH_DIFF_MAX_FILES = 80` 筆檔案統計與 `commits_touched`，不含原始 diff 內容）。
- **超限裁切記錄**：若單項預覽被裁切或為符合 256 KiB 上限而縮減 `messages_preview`／`tool_activity` 筆數，於 `document["coverage"]` 與回應之 `completeness.coverage` 標記 `document_truncated: true`（原因加入 `"result_document_bounded"`）。完整訊息原文仍可透過既有 `service.session_read` 與 `turn_marker` 游標按需讀取。

## 3. 受管 Worktree 有限差異讀取、記憶體 Memo 與結果 Commit（Changeset）

### 3.1 BAT Git 通道參數、未提交狀態與無寫入 Memo 快取

| 項目 | 規格與來源 (`path:line`) |
|---|---|
| **通道與參數名稱** | 嚴格透過唯讀 Fleet `checkpoints._read_fleet(ops).client(host)`（同 `checkpoints.preview` `checkpoints.py:214-229`）與 `lifecycle.py:1058-1087`、`orchestrate.py:42-61` 之真實參數與回傳鍵名呼叫：<br>- `git:getRoot {"cwd": wt}`<br>- `git:log {"cwd": wt, "count": N}` → `[{"hash": str, ...}]`<br>- `git:diff-files {"cwd": wt, "commitHash": h}` → `[{"file": str, "status": str}]`<br>- `git:diff {"cwd": wt, "commitHash": h, "filePath": path}` → `str`<br>- `orchestrate.diff_stats(diff)` → `{"files": int, "additions": int, "deletions": int}` |
| **Per-Commit 統計聚合標記** | 因受制於 BAT pipe 緩衝區上限（超過時 BAT 對該檔 `git:diff` 回傳 `""`，見 `lifecycle.py:1049-1052`；測試中以空字串 `commit_diffs` 項目模擬，不於 `tests/mockbat.py` 新增常數），變更係以獨立之變更摘要 walker（`pm_attempt_results.collect_changes_summary`，比照 `lifecycle._branch_diff` 但以 Attempt 凍結之 `source_sha` 為基準）逐一由舊至新掃描 `(base_commit..head_commit]` 內各 commit（呼叫 `git:log {"cwd": wt, "count": max_commits + 1}`，預設上限 `BRANCH_DIFF_MAX_COMMITS = 30`、`BRANCH_DIFF_MAX_FILES = 80`）。若 `max_commits` 個 commit 內未達 `source_sha` 則設原因 `"commit_limit_exceeded"`；若 log 結束仍未達 `source_sha` 則設原因 `"base_commit_not_ancestor"`（兩者皆設 `complete: false` 且不加總）。統計值為**各 commit 變動之加總**而非壓平後之淨 diff，故 `summary.aggregation` 固定標為 `"per_commit"`，且每個檔案項目皆存 `{path, status, additions, deletions, commits_touched}`（不存原始 diff 文字）。當單檔 `git:diff` 回傳空字串或 `BatError` 時，將路徑列入 `unavailable: list[str]`，該檔 `additions: "unknown", deletions: "unknown"`（絕不填 `0`）。 |
| **成本控制與記憶體 LRU Memo（0 DB 寫入）** | 固定 `(base_sha, head_sha)` 間之已提交變更為不可變事實：<br>1. **收集器計算一次**：收集器在回合邊界固定 `session_results` 回執時計算 `(base_commit, head_sha)` 之變更摘要並存入 `session_results.document["changes_summary"]`。<br>2. **`/result` 絕不內聯計算**：`/result` 永遠直接回傳最新 `session_results.document["changes_summary"]`（0 次 BAT IPC 呼叫）。<br>3. **`/changes` 記憶體 LRU Memo（不寫 DB）**：`/changes` 先以單次 `git:log {"cwd": wt, "count": 1}` 取得 `live_head_commit`（標記 `head_freshness: "live"`）。若 `live_head_commit == receipt_head_sha` 且回執已有完整摘要，直接回傳回執內已存摘要；若 `live_head_commit` 與回執不同，先查服務端**純記憶體 LRU 快取**（鍵值 `(attempt_id, base_sha, live_head_commit)`，容量上限 `CHANGESET_MEMO_MAX_ENTRIES = 128` 筆，存活時間 `CHANGESET_MEMO_TTL_S = 300.0s`）。未命中時才以每 `attempt_id` 單飛任務（single-flight shared `asyncio.Task`）與總時間預算 `CHANGESET_TOTAL_BUDGET_S = 25.0s` 計算並放入記憶體 Memo（**0 次 DB 寫入，重啟即丟棄**）。若遭遇 `BatError`、`ConnectionLost` 或逾時，回傳 `partial` 並標記 `"worktree_unreachable"` 或 `"bat_unreachable"`（絕不回傳 500）。 |
| **未提交變更（Uncommitted Changes）** | 1. **BAT `git:status` 空陣列絕非乾淨證明**：依 `docs/design/checkpoints.md:20` 與 `docs/design/worktree-merge.md:50`，BAT `git:status` 在失敗時亦回傳 `[]` 且可能刷新 `.git/index`。因此：若 `git:status {"cwd": wt}` 回傳非空陣列，記 `uncommitted = {"count": len(entries), "files": entries, "evidence": "bat_git_status_nonempty"}`；若主機具備唯讀 SSH porcelain 驗證（`checkpoints.md:20`）則以其實際結果記 `"ssh_git_status_porcelain"`；否則（含 `git:status` 回傳 `[]` 或失敗），一律記 `uncommitted = {"count": "unknown", "files": "unknown", "evidence": "unproven", "reason": "bat_empty_status_not_clean_proof"}`，**絕不標為 `0` 或 clean**。<br>2. **R1 不提供未提交檔案 diff**：未提交檔案固定標記 `diff_available: false, unavailable_reason: "uncommitted_diff_not_supported_by_bat"`。 |
| **`/diff` 嚴格窄化契約** | `pm_work_attempt_diff_get`（`/diff`）：<br>- `commit`（40-hex SHA）與 `path`（相對於 repo root 之正規化路徑）**皆為必填**；無「最新修改該檔之 commit」預設值，亦無 `scope=worktree`。<br>- `commit` 必須位於該 Attempt 已掃描之 `(base_commit..head_commit]` 清單內；`path` 必須屬於 `git:diff-files {"cwd": wt, "commitHash": commit}` 為該 `commit` 回傳之 `file` 清單。凡 `commit` 不在範圍內或 `path` 不在該 `commit` 變更清單內（含未提交檔案），一律回傳 `404 NotFoundError`（`PM_DIFF_NOT_FOUND`）。<br>- 回傳單一 `(commit, path)` 之有界 diff 文字（上限 256 KiB，超過時裁切並設 `truncated: true`）；若 BAT `git:diff` 回傳空字串，回傳 `{"available": false, "reason": "diff_exceeded_pipe_limit"}` 而非空字串 diff。 |
| **Manual / Foreign 唯讀與前置 Registry 閘門** | 在發起**任何** BAT IPC 呼叫前，`/changes` 與 `/diff` 必須先通過成員資格、`observe` scope、可見性、lineage 與 **registry 檢核**（`registry.get(host, session_id)["start_operation_id"] == handoff_operation_id`）。若 registry 檢核失敗，**發起 0 次 BAT 呼叫**：`/changes` 回傳 `completeness.status == "unavailable"`（原因 `"session_not_managed_by_attempt"`），`/diff` 直接回傳 `404 PM_DIFF_NOT_FOUND`。 |

### 3.2 固定結果 Commit（`fixed_result_commit`）記錄規則（無 `dirty_count == 0` 前置條件）

未提交之工作區修改永遠不屬於任何 commit；而已提交之 Git `HEAD` 本身即為不可變之 commit 物件。因此**無 `dirty_count == 0` 前置條件**，於以下四種中心回執產生時記錄 `fixed_result_commit`（優先序由高至低）：

### 4.1 八種標準執行狀態映射表（有界投影，可恢復之 `needs_attention` 絕非 `failed`）

|---|---|---|---|
| **`failed`** | **僅限終態失敗**：父 `work.start` 為 `operation_status == "failed"`（`stage == "start_failed"`），或 `operation_status == "cancelled"` 且無 session（`session_id is None`，`state_reason: "start_cancelled"`），或最新匹配回執 `boundary_reason == "agent_error"` | `work_start` 或 `result_receipt` | `operation_status == "failed"`（`stage == "start_failed"`）、`operation_status == "cancelled"`（無 session），或回執 `document["boundary_reason"] == "agent_error"` |

| **`starting`（無 session）** | `handoff` 啟動中或於 `handoff` 階段進入可恢復之 `needs_attention`（`stage == "starting"` 且尚未產生 session） | `work_start` | `stage == "starting"` 且 `session_id is None`（若 `operation_status == "needs_attention"`，附 `attention: {code, message, resumable: true}`） |

| **`active`** | Session 正在串流或執行回合 | `inventory_observation` | `streaming is True` 或 `runtime_status in {"running", "streaming", "active"}` |
| **`starting`（session 啟動中）** | Session 剛啟動（`runtime_status == "starting"`） | `inventory_observation` | `loaded is True` 且 `runtime_status == "starting"` |
| **`unknown`（未載入歷史 session）** | `loaded is False` 且無程序結束證據（未載入之歷史 session 絕不視為死亡程序，`pm_workload_sources.py:575-578`，帶 `unloaded_history_session`） | `inventory_observation` | `loaded is False` 且 `runtime_status not in {"exited", "stopped"}`、`gone_at is None` |
| **`turn-ended`** | 最新回執涵蓋目前 `turn_marker`（且 session 處於 `loaded is True`、非串流、無 `pending`、未結束） | `result_receipt` | 最新 `session_results` 回執之 `turn_marker == attempt.turn_marker` |

## 7. 完整度分類、原因與覆蓋率（Completeness）

統一採用 `status: "complete" | "partial" | "unavailable"`，重用 `session_reading.INCOMPLETE_REASONS`（`src/bat_agent_connector/session_reading.py:15-26`）與 `pm_evidence` 覆蓋率語彙（`src/bat_agent_connector/pm_evidence.py:29-42,1677-1708`）：

- **`complete`**：`stage == "started"`、`loaded is True`、已有匹配目前 `turn_marker` 之回執且 transcript 無截斷或缺口、受管 worktree 已提交變更 `summary.complete is True` 且 `unavailable == []`、無 `source_digest_conflict` 且 `document_truncated is False`。
- **`partial`**：已取得部分有效證據（如 `work_attempts` 啟動狀態、或已固定之 `session_results` 回執、或有對話但部分檔案 diff 超過 pipe 上限／未提交狀態為 `"unknown"`／回執預覽因 256 KiB 上限裁切／尚未收集到回合邊界），但存在至少一項 `reasons` 缺口。
- **`unavailable`**：啟動在產生 session 前即失敗／取消且無任何 `session_results` 回執，或來源非該 Attempt 受管（`"session_not_managed_by_attempt"`）且無可用回執。
- **標準原因碼（`completeness.reasons`）**：
