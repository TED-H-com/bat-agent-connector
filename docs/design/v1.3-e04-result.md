## 1. Result 信封契約（Envelope：`pm-work-attempt-result/v1`）

每個由 `work.start` 建立之 `attempt_id`（`att_<32hex>`）對應單一標準化 Result 信封。所有欄位皆標明既有資料來源，且嚴格遵守三項不變量：
1. **狀態分離**：模型自述（`self_reported`）、驗證（`verified`）、需求驗收（`accepted`）、合併（`merged`）與部署（`deployed`）分屬獨立欄位；程序退出碼 `0`、停止串流或助手輸出「已完成／全部完成」永遠只記為 `self_reported`，絕不等於驗證通過或需求驗收（計畫 §10.2）。
2. **未知誠實揭露**：無證據或未提供之指標一律維持 `"unknown"`（字串常數），絕不填 `0`、`false` 或空陣列偽裝為零值（Hard Rule 6、計畫 §10.2）。
3. **用量不換算金額**：僅回傳來源原生提供之 token、回合數與時間；缺少即標 `"unknown"`，且信封禁止出現 `cost_usd` 或任何訂閱額度折算金額欄位（計畫 §10.2）。

### 1.2 `execution.state_facets` 狀態分離規則

| Facet 欄位 | 允許值 | 唯一合法證據來源 | 明確禁止之推論 |

## 2. 儲存與重播決策（Storage：`session_results` 固定回執表＋讀取時動態投影）

### 2.1 決策與理由

**決策**：在 R1 採用**最小混合設計（Minimal Hybrid）**——引入 E00 §4.2 定義之 `session_results` 唯讀追加（append-only）資料表（`docs/design/v1.3-e00-baseline.md:211`），專門持久化**回合結束（turn-end）與觀測檢查點之固定來源回執（Fixed Result Snapshot）**；完整 Result 信封則於讀取時結合 `work_attempts`、`operations`、`session_results`、`pm_execution_verification`、`pm_quality_reviews`、`pm_delivery_lineage` 與即時 BAT IPC 動態組裝。

**為何不能僅靠既有資料表於讀取時重建（Why existing receipts alone do not suffice）**：
1. **`sessions_observed` 為覆寫式快取**：`sessions_observed`（`src/bat_agent_connector/task_journal.py:227-237`、`inventory.py:197-205`）以 `ON CONFLICT(host, session_id) DO UPDATE` 覆寫單行，不保留歷史觀測位置，且未記錄該回合之助手最終摘要、當下 worktree `HEAD` SHA 與有限差異統計。當同一 session 進入下一輪（E03 `work.follow_up`）或 BAT 主機斷線時，上一輪的固定成果將被覆蓋或無法離線重播。
2. **`registry.get_turn` 為揮發性記憶體狀態**：`SessionRegistry._turns`（`src/bat_agent_connector/registry.py:322-366`）僅存於記憶體，Connector 重啟後即消失。
3. **`pm_execution_runtime` 僅服務批次子操作**：`pm_execution_runtime`（`src/bat_agent_connector/pm_execution_runtime.py:73-89`）綁定 `pm.work_batch.start` 之 `batch_id`，不涵蓋 `work.start` 啟動之 `work_attempts`。
4. **同位置異雜湊衝突偵測（Replay Integrity）**：計畫 §10.4 與 E00 §4.2 要求同一 `(workspace_id, source_key, source_generation, source_position)` 重播若出現不同 `digest` 必須明確拒絕並留下稽核證據；既有表無此約束。

**為何保持最小化（不重複儲存）**：`session_results` **不複製**完整對話 transcript、不另存驗證與 PR 狀態，僅固定保存當下之 `sources`、`conversation.latest_assistant_summary`、`execution` 快照與 `changes` 摘要（`live_head_commit`、統計與 `unavailable` 清單）。當 BAT 斷線或 Connector 重啟時，讀取端點直接從最新一筆 `session_results` 重建最後固定 Result 並將完整度標示為 `partial`（原因：`"bat_unreachable"`）。

### 2.2 冪等 Schema DDL（不分配 `user_version`、無 Data Step）

於 `src/bat_agent_connector/pm_work_attempt_results.py`（由 `TaskJournal._init_db` 呼叫 `ensure_schema(conn)`）定義冪等 DDL：

```sql
CREATE TABLE IF NOT EXISTS session_results (
    sequence INTEGER PRIMARY KEY AUTOINCREMENT,
    result_id TEXT NOT NULL UNIQUE,
    workspace_id TEXT NOT NULL,
    work_item_id TEXT,
    attempt_id TEXT,
    adapter_kind TEXT NOT NULL,
    source_key TEXT NOT NULL,
    source_generation TEXT NOT NULL,
    source_position TEXT NOT NULL,
    decoder_version TEXT NOT NULL,
    digest TEXT NOT NULL,
    envelope TEXT NOT NULL,
    observed_at REAL NOT NULL,
    recorded_at REAL NOT NULL,
    UNIQUE(workspace_id, source_key, source_generation, source_position)
);
CREATE INDEX IF NOT EXISTS session_results_by_attempt
    ON session_results(workspace_id, attempt_id, sequence DESC);
CREATE INDEX IF NOT EXISTS session_results_by_work
    ON session_results(workspace_id, work_item_id, sequence DESC);

CREATE TRIGGER IF NOT EXISTS session_results_no_update
BEFORE UPDATE ON session_results BEGIN
    SELECT RAISE(ABORT, 'session_results is append-only');
END;
CREATE TRIGGER IF NOT EXISTS session_results_no_delete
BEFORE DELETE ON session_results BEGIN
    SELECT RAISE(ABORT, 'session_results is append-only');
END;
```

- **冪等重播與衝突規則**：寫入 `record_session_result` 時，若 `(workspace_id, source_key, source_generation, source_position)` 已存在：
  - 若既有 `digest == new_digest`：視為冪等重播，直接回傳既有 `result_id`（0 寫入）。
  - 若既有 `digest != new_digest`：保留既有固定回執不覆寫，拋出 `ConflictError("PM_RESULT_DIGEST_CONFLICT")` 並透過 `ops.db.emit_event` 發出 `work.attempt.result_conflict` 稽核事件，同時將讀取回應之 `completeness.status` 降為 `"partial"`（原因加入 `"source_digest_conflict"`）。

## 3. 受管 Worktree 有限差異讀取與歸因（Changeset）

### 3.1 基準、即時結果與 64 KB Pipe 限制處理

E04 補齊盤點報告之最大缺口：為 Attempt 自有受管 worktree 提供**檔案清單與統計（`/changes`）**及**單檔按需差異（`/diff`）**，重用 `src/bat_agent_connector/channels.py:48-54` 已列入 `READ_CHANNELS` 白名單之 `git:getRoot`、`git:log`、`git:status`、`git:diff-files`、`git:diff`，以及 `lifecycle._branch_diff`（`src/bat_agent_connector/lifecycle.py:1042-1096`）與 `orchestrate.diff_stats`（`src/bat_agent_connector/orchestrate.py:42-51`）之實戰防護：

| 項目 | 規格與來源 (`path:line`) |
|---|---|
| **工作區歸因與擁有權驗證** | 由 `execution_sources.resolve(ops, execution_operation_id)`（`execution_sources.py:46-74`）解析 `{host, worktree_path, session_id}`，並檢核：(1) `execution_operation_id == attempt.execution_operation_id`；(2) `session_authority.is_managed_session`（`session_authority.py:40`）為真；(3) `git:getRoot` 回傳之標準化路徑與建立回執之 `worktree_path` 一致（`lifecycle.py:72-75`）。 |
| **Manual / Foreign 唯讀保護** | 若 session 為 manual、foreign 或缺建立回執，拒絕將其歸因為受管 Attempt 寫入來源（`PM_ATTEMPT_SOURCE_NOT_MANAGED`）；整個讀取過程僅呼叫 `READ_CHANNELS`，**0 次主機寫入或 `ORCHESTRATE_CHANNELS` 呼叫**。 |
| **Base Commit（固定基準）** | 取自 `work.start` admission 快照之 `code_source.source_sha`（`pm_work_start.py:1352`、`repository_sync.py:314`），標記 `base_freshness: "fixed_admission"`。 |
| **Live Result Commit（即時結果）** | 讀取當下對受管 `worktree_path` 呼叫 `lifecycle._candidate_head`（`lifecycle.py:77-81`，即 `git:log` `maxCount=1`），取得 `live_head_commit` 並明確標記 `head_freshness: "live"`。 |
| **Commit-by-Commit 收集上限** | 沿用 `lifecycle.py:55-56,1042-1096`：以 `git:log`（`maxCount = BRANCH_DIFF_MAX_COMMITS + 1 = 31`）自 `live_head_commit` 往回走至 `base_commit`。若超過 30 個 commits 未遇到 `base_commit`（或歷史分叉），停止走訪並標記 `complete: false`、`truncation_reason: "commit_limit_exceeded"`（或 `"base_not_ancestor"`）。 |
| **64 KB Pipe 限制與 `unavailable` 清單** | 對每個 commit 呼叫 `git:diff-files` 收集變更路徑（上限 `BRANCH_DIFF_MAX_FILES = 80`）；再逐檔呼叫 `git:diff {path, commit, file}` 並以 `orchestrate.diff_stats`（`orchestrate.py:42-51`）計算新增／刪除行數。因 BAT IPC Named Pipe 單次無緩衝寫入上限為 64 KB（`tests/mockbat.py:345`、`lifecycle.py:1079-1085`），當 `git:diff` 回傳空字串 `""` 或 `BatError` 時，**絕不將行數記為 `0`**，而是將該檔路徑加入 `unavailable: list[str]`，該檔案項目設為 `{"path": file, "status": status, "insertions": "unknown", "deletions": "unknown", "diff_available": false, "unavailable_reason": "diff_exceeded_pipe_limit_or_binary"}`，且頂層 `complete: false`。 |
| **未提交變更（Working Tree Dirty）** | 以 `orchestrate._git_dirty`（`orchestrate.py:54-61`，呼叫 `git:status`）讀取 `dirty_files`（含 `path`、`status`、`staged`）。未提交檔案一併列於 `/changes` 之 `dirty_files`，並允許透過 `/diff?path=<file>&scope=worktree` 按需呼叫不帶 `commit` 之 `git:diff {path, file}` 讀取（同樣受 64 KB `unavailable` 規則保護）。 |
| **單檔按需 Diff（`/diff`）** | 預設讀取該檔在 `(base_commit..live_head_commit]` 內最新修改該檔之 commit diff（或指定 `commit=<sha>`／`scope=worktree`）。若內容超過 64 KB 或 BAT 回傳空字串，回傳 `diff: null, available: false, unavailable_reason: "diff_exceeded_pipe_limit_or_binary"`。 |

### 3.2 固定結果 Commit（`fixed_result_commit`）何時記錄、由誰記錄

`live_head_commit` 隨工作區變動而改變；`fixed_result_commit` 則僅在中心服務寫入不可變回執時記錄，並載明來源與記錄者（優先順序由高至低）：

| 優先序 | 事件／階段 | `source_kind` | `source_id` | `recorded_by`（記錄者） | 記錄時機與來源 (`path:line`) |
|---:|---|---|---|---|---|
| 1 | 交付整合／PR 建立或合併 | `"integration"` | `integration` 之 `operation_id` | 觸發整合之授權 `principal.actor` | `integration.prepare` / `create_pr` / `merge` 驗證並固定 `head_sha` 或 `merge_commit_sha` 時（`lifecycle.py:1143,1289`、`pm_delivery_lineage.py:309`） |
| 2 | 受管執行驗證完成 | `"execution_verification"` | `pm_execution_verification.verification_id` | 觸發 `pm.execution.verify` 之 `actor` | `pm.execution.verify` 於乾淨受管 worktree 驗收 `candidate_head_sha` 並寫入 `pm_execution_verification` 時（`pm_execution_verification.py:322`） |
| 3 | 外部驗證證詞登錄 | `"session_verification"` | `verifications.operation_id` | 呼叫 `session.record_verification` 之 `actor` | `verification.py:33-34` 驗證乾淨候選 worktree `HEAD == commit_sha` 並寫入 `verifications` 時 |
| 4 | 回合結束觀測快照 | `"turn_end_snapshot"` | `session_results.result_id` | `"system:connector_observer"` 或呼叫讀取／等待之 `actor` | 當 `state` 進入 `'turn-ended'` 或 `'process-ended'` 且工作區 `dirty_count == 0`、`live_head_commit != base_commit` 時，寫入 `session_results` 固定快照 |

## 4. 執行狀態映射與持久化／即時邊界（Execution State）

### 4.1 八種標準執行狀態映射表

依計畫 §10.2，Result 將 E02 操作階段、BAT session 觀測與 `session_wait(until="turn-end")` 映射為 8 種狀態，並於 `execution.state_source` 標明判定來源：

| `execution.state` | 判定條件（由上而下優先匹配） | E02 `stage` / `operation_status` (`pm_work_start.py:1600-1635`) | Session 觀測 (`sessions_observed` / `service.session_status` `service.py:567`) | `session_wait(until="turn-end")` / Turn 狀態 (`service.py:806`、`pm_session_quiescence.py:121`) |
|---|---|---|---|---|
| **`failed`** | 父 `work.start` 或子操作進入失敗終態，或 BAT session 回報 `status == "error"` | `stage == "start_failed"` 或 `operation_status in ("failed", "cancelled")` | `raw_status == "error"` 或最後事件為 `session.error` | `wait_status == "error"` |
| **`accepted`** | `work.start` 已受理或正在準備綁定／工作包，尚未進入 `handoff` 啟動 | `stage in ("accepted", "preparing", "package_prepared")` | `session_id is None` | 不適用（尚未派發 session） |
| **`starting`** | `handoff`（`repository.continue`）已建立並啟動中，或首句提示尚未確認寫入 transcript | `stage == "starting"`（或 `stage == "started"` 但 `prompt_accepted == False` 且 turn 尚未結束） | `session_id` 未產生，或剛產生且 `working` 為真、`prompt_accepted` 未確認 | `turn.status == "running"`（首句進行中） |
| **`unknown`** | `handoff` 處於 `uncertain` 待對帳，或 BAT 主機斷線／逾時無法取得即時狀態 | `stage == "start_unknown"` 或 `handoff` 為 `uncertain` | `BatError` / `OfflineError` / 觀測過期（僅能退回 `session_results` 快照） | `wait_status == "unknown"` |
| **`waiting`** | BAT session 等待使用者／工具權限或問題回覆 | `stage == "started"` | `pendingInput` 非空（`summarize_pending` 非 `None`）或 `raw_status in ("waiting", "waiting_input", "needs_input")` | `quiescence.status == "active"`（reason: `"session_waiting_for_input"`） |
| **`active`** | BAT session 正在執行模型推論或工具呼叫 | `stage == "started"` | `working is True` 或 `raw_status in ("running", "working", "busy", "streaming")` | `turn.status == "running"` 且無 `pendingInput` |
| **`process-ended`** | BAT 回報 session 程序已終止／關閉，或從活躍 session 清單消失但有歷史紀錄 | `stage == "started"` | `raw_status in ("exited", "stopped", "closed", "terminated")` 或 live list 缺席但 `session_read` 存在歸檔 | `turn.status in ("completed", "idle")` 且 process 不再存活 |
| **`turn-ended`** | 首句已受理（`prompt_accepted == True`），目前無進行中 turn 且無待決輸入 | `stage == "started"` 且 `operation_status == "succeeded"` | `working is False`、`pendingInput is None`、`raw_status in ("idle", "completed", "ready")` | `session_wait(until="turn-end")` 回傳 `status == "turn-end"`，或 `pm_session_quiescence.evaluate` 回傳 `"quiescent"` |

## 7. 完整度分類、原因與覆蓋率（Completeness）

統一採用單一分類法 `status: "complete" | "partial" | "unavailable"`，重用 `session_reading.INCOMPLETE_REASONS`（`src/bat_agent_connector/session_reading.py:15-26`）與 `pm_evidence` 覆蓋率語彙（`src/bat_agent_connector/pm_evidence.py:29-42,1677-1708`）：

### 7.1 狀態判定規則

- **`last_successful_observation`**：`{"observed_at": float | null, "result_id": str | null, "source_position": dict | null, "live_head_commit": str | "unknown"}`，當 BAT 失聯時讓使用者與 agent 清楚得知最後一次成功觀測之時間與回執。
