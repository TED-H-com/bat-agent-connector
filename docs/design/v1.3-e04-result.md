## 1. Result 信封契約（Envelope：`pm-work-attempt-result/v1`）

每個由 `work.start` 建立之 `attempt_id`（`att_<32hex>`）對應單一標準化 Result 信封。所有欄位皆標明程式碼中實際存在之來源與 `path:line`，且遵守三項不變量：
1. **狀態分離**：模型自述（`self_reported`）、驗證（`verification`）、需求驗收（`acceptance`）、品質審閱（`review_decision`）、合併（`merge`）與部署（`deployment`）分屬獨立欄位；助手文字宣稱「已完成」或 `turn_done == True` 永遠只記為 `self_reported`，絕不等於驗證通過或需求驗收（計畫 §10.2）。
2. **未知誠實揭露**：無證據或來源未提供之指標一律維持 `"unknown"`，絕不填 `0`、`false` 或空陣列偽裝為零值或乾淨狀態（Hard Rule 6、計畫 §10.2）。
3. **用量不換算金額、不混用操作時間**：僅回傳來源原生提供之 token 與回合數；BAT 未提供之欄位（含單回合耗時 `duration_seconds`）維持 `"unknown"`，且禁止出現 `cost_usd`（計畫 §10.2）。

## 2. 儲存與單一系統收集器決策（Storage & Single Server-Side Collector）

### 2.1 為何需要 E00 §4.2 `session_results` 表

1. **`sessions_observed` 為覆寫式快取**：`sessions_observed`（`inventory.py:197-205`）以 `ON CONFLICT(host, session_id) DO UPDATE` 覆寫單行，不保留歷史回合位置、助手摘要或當下 `HEAD` commit 與變更統計。
2. **`registry.get_turn` 為揮發性記憶體狀態**：`registry.py:322-366` 於 Connector 重啟後消失。
3. **無讀取者時亦須固定成果（計畫 §13「UI 關閉／斷線」）**：即使沒有任何瀏覽器或 MCP 客戶端呼叫讀取 API，回合結束時中心服務仍必須固定該輪 Result 並留存可引用之 `result_id`。

### 2.2 讀取絕不寫入（Reads Never Write）：單一背景收集器（`actor="connector"`）

- **鐵則**：所有讀取端點（`/result`、`/changes`、`/diff` 與對應 RPC／MCP tools）為**純讀取（0 資料庫寫入、0 `api_events` 發出）**。固定回執僅由單一服務端收集器（`AttemptResultCollector`）以系統身分 `actor="connector"` 寫入，絕不將回執歸因於碰巧發起讀取之使用者或 agent。
- **觸發訊號（不建立新 BAT 訂閱）**：
  1. **即時訊號**：重用 `BatClient._read_loop` 已維護之 `recent_events` 環狀緩衝區（`client.py:288-301`），當觀測到 `channel in ("agent:turn-end", "agent:result", "agent:error")` 且 `sessionId` 對應受管 Attempt 時排入收集。
  2. **定時巡檢 Fallback**：重用 `Inventory.loop` 週期（`inventory.py:65` `interval_s = 60.0`、`inventory.py:341-353`），每輪 `refresh_host` 完成後掃描該 `host` 上已進入 `stage == "started"` 之受管 Attempt。
- **收集範圍（Scope）**：僅限 `work_attempts` → `pm_work_start_children(slot='handoff')` → `execution_operation_id` 已綁定 `{host, session_id}` 之受管 Attempt。
- **資源與併發邊界（Bounds）**：
  - 每個 `host` 同一時間最多執行 **1 個**收集工作（per-host single-flight `asyncio.Lock`）。
  - 嚴格遵守 `channels.py:130-148` 之通道逾時（`claude:get-session-state`: `60.0s`、`git:log`: `15.0s`、`git:diff-files`: `15.0s`、`git:diff`: `20.0s`、`DEFAULT_TIMEOUT`: `15.0s`）。
  - **略過重複收集**：若 `session_results` 針對該 `(workspace_id, source_key, source_generation)` 最新一筆紀錄已具有相同 `source_position` 且 `turn_done == True`，直接略過（0 額外 Git IPC）。
- **失敗退避與重啟恢復（Backoff & Restart）**：收集遭遇 `BatError` 或連線中斷時，沿用 `Inventory` 指數退避規則（`min(max_backoff_s, interval_s * 2 ** min(failures, 6))`，上限 `600.0s`，`inventory.py:68,335-337`）。Connector 重啟後，收集器自 SQLite 讀取尚未擁有對應 `source_position` 終態回執之受管 `work_attempts` 自動補收，無須客戶端介入。

### 2.3 冪等 Schema DDL、雜湊範圍與唯一性（對齊 E00 §4.2）

完全遵循 `docs/design/v1.3-e00-baseline.md:211` 之欄位（保留 `operation_id` 指向 `execution_operation_id` 以直接支援 `pm_source_lineage` 撤回檢核）與五鍵唯一性，不分配 `user_version`、無 Data Step：

```sql
CREATE TABLE IF NOT EXISTS session_results (
    sequence INTEGER PRIMARY KEY AUTOINCREMENT,
    result_id TEXT NOT NULL UNIQUE,
    workspace_id TEXT NOT NULL,
    attempt_id TEXT,
    source_key TEXT NOT NULL,
    source_generation TEXT NOT NULL,
    source_position TEXT NOT NULL,
    digest TEXT NOT NULL,
    document TEXT NOT NULL,
    observed_at REAL NOT NULL,
    collected_at REAL NOT NULL,
    operation_id TEXT NOT NULL,
    UNIQUE(workspace_id, source_key, source_generation, source_position, digest)
);
CREATE INDEX IF NOT EXISTS session_results_by_attempt
    ON session_results(workspace_id, attempt_id, sequence DESC);
CREATE INDEX IF NOT EXISTS session_results_by_position
    ON session_results(workspace_id, source_key, source_generation, source_position, sequence ASC);

CREATE TRIGGER IF NOT EXISTS session_results_no_update
BEFORE UPDATE ON session_results BEGIN
    SELECT RAISE(ABORT, 'session_results is append-only');
END;
CREATE TRIGGER IF NOT EXISTS session_results_no_delete
BEFORE DELETE ON session_results BEGIN
    SELECT RAISE(ABORT, 'session_results is append-only');
END;
```

- **`digest` 計算範圍（排除 Worktree 與外部狀態）**：`digest` 僅對該 `source_position` 下**源自對話來源本身之正規化內容**計算 SHA-256：`{source_key, source_generation, source_position, decoder_version, turn_marker, turn_done, normalized_public_messages}`。**明確排除** worktree `head_sha`、`uncommitted`、changeset 統計、驗證與交付紀錄（這些觀測值存於 `document` 內、位於 `digest` 之外）。因此，agent 或工具在 turn-end 後才完成 git commit **絕不會引發假性雜湊衝突**。
- **同位置異雜湊與並發寫入規則**：
  - 兩個收集器同時收集同一位置且算出相同 `digest` 時，以 `INSERT OR IGNORE` 冪等保留單一列（0 重複列）。

## 3. 受管 Worktree 有限差異讀取、快取與結果 Commit（Changeset）

### 3.1 BAT Git 通道參數、未提交狀態與成本控制

| 項目 | 規格與來源 (`path:line`) |
|---|---|
| **通道與參數名稱** | 嚴格使用 `lifecycle.py:1058-1087` 與 `orchestrate.py:42-61` 之真實參數與回傳鍵名：<br>- `git:getRoot {"cwd": wt}`<br>- `git:log {"cwd": wt, "count": N}` → `[{"hash": str, ...}]`<br>- `git:diff-files {"cwd": wt, "commitHash": h}` → `[{"file": str, "status": str}]`<br>- `git:diff {"cwd": wt, "commitHash": h, "filePath": path}` → `str`<br>- `orchestrate.diff_stats(diff)` → `{"files": int, "additions": int, "deletions": int}` |
| **Per-Commit 統計聚合標記** | 因受制於 BAT 64 KB pipe 上限（`tests/mockbat.py:345`、`lifecycle.py:1049-1052`），變更係逐一掃描 `(base_commit..head_commit]` 內各 commit（上限 `BRANCH_DIFF_MAX_COMMITS = 30`、`BRANCH_DIFF_MAX_FILES = 80`，`lifecycle.py:1042-1043`）。統計值為**各 commit 變動之加總**而非壓平後之淨 diff，故 `summary.aggregation` 固定標為 `"per_commit"`，且 `/changes` 中每個檔案項目皆列出 `commits_touched: list[40hex]`（修改過該檔之 commit 清單）。當單檔 `git:diff` 回傳空字串或 `BatError` 時，將路徑列入 `unavailable: list[str]`，該檔 `additions: "unknown", deletions: "unknown"`（絕不填 `0`）。 |
| **成本控制與單飛快取（Single-Flight & Budget）** | 固定 `(base_sha, head_sha)` 間之已提交變更為不可變事實：<br>1. **收集器計算一次**：收集器在固定 `session_results` 回執時計算 `(base_commit, head_sha)` 之變更摘要並存入 `session_results.document["changes_summary"]`。<br>2. **`/result` 絕不內聯計算**：`/result` 永遠直接回傳最新 `session_results.document["changes_summary"]`（0 次 `git:diff-files`/`git:diff` IPC 呼叫）。<br>3. **`/changes` 按需重算與時間預算**：`/changes` 先以單次 `git:log {"cwd": wt, "count": 1}` 取得 `live_head_commit`（標記 `head_freshness: "live"`）。若 `live_head_commit == receipt_head_sha`，直接回傳已存摘要；僅當 `live_head_commit` 改變時，以每 `attempt_id` 單飛鎖（single-flight lock）與總時間預算 `CHANGESET_TOTAL_BUDGET_S = 25.0s` 計算新範圍，若逾時則將未讀完之檔案列入 `unavailable`（原因 `"changeset_time_budget_exceeded"`）。 |
| **未提交變更（Uncommitted Changes）** | 1. **BAT `git:status` 空陣列絕非乾淨證明**：依 `docs/design/checkpoints.md:20` 與 `docs/design/worktree-merge.md:50`，BAT `git:status` 在失敗時亦回傳 `[]` 且可能刷新 `.git/index`。因此：若 `git:status {"cwd": wt}` 回傳非空陣列，記 `uncommitted = {"count": len(entries), "files": entries, "evidence": "bat_git_status_nonempty"}`；若主機具備唯讀 SSH porcelain 驗證（`checkpoints.md:20`）則以其實際結果記 `"ssh_git_status_porcelain"`；否則（含 `git:status` 回傳 `[]` 或失敗），一律記 `uncommitted = {"count": "unknown", "files": "unknown", "evidence": "unproven", "reason": "bat_empty_status_not_clean_proof"}`，**絕不標為 `0` 或 clean**。<br>2. **R1 不提供未提交檔案 diff**：BAT 無不帶 `commitHash` 之受驗證 `git:diff` 支援；未提交檔案項目固定標記 `diff_available: false, unavailable_reason: "uncommitted_diff_not_supported_by_bat"`。 |
| **`/diff` 嚴格窄化契約** | `pm_work_attempt_diff_get`（`/diff`）：<br>- `commit`（40-hex SHA）與 `path`（相對於 repo root 之正規化路徑）**皆為必填**；無「最新修改該檔之 commit」預設值，亦無 `scope=worktree`。<br>- `commit` 必須位於該 Attempt 已掃描之 `(base_commit..head_commit]` 清單內；`path` 必須屬於 `git:diff-files {"cwd": wt, "commitHash": commit}` 為該 `commit` 回傳之 `file` 清單。<br>- 凡 `commit` 不在範圍內或 `path` 不在該 `commit` 變更清單內，一律回傳 `404 NotFoundError`（`PM_DIFF_NOT_FOUND`）。 |
| **Manual / Foreign 唯讀保護** | 透過 `execution_sources.resolve`（`execution_sources.py:46-74`）與 `session_authority.is_managed_session`（`session_authority.py:40`）驗證；manual 與 foreign sessions 永遠唯讀，拒絕綁定為受管 Attempt 變更來源，0 次主機寫入。 |

## 7. 完整度分類、原因與覆蓋率（Completeness）

統一採用 `status: "complete" | "partial" | "unavailable"`，重用 `session_reading.INCOMPLETE_REASONS`（`src/bat_agent_connector/session_reading.py:15-26`）與 `pm_evidence` 覆蓋率語彙（`src/bat_agent_connector/pm_evidence.py:29-42,1677-1708`）：

- **`complete`**：`stage == "started"`、`loaded is True`、即時 `session_read` 無截斷且無缺口、受管 worktree 已提交變更 `summary.complete is True` 且 `unavailable == []`、無 `source_digest_conflict`。
- **`partial`**：已取得部分有效證據（如 `work_attempts` 啟動狀態、或已固定之 `session_results` 回執、或有對話但部分檔案 diff 超過 64 KB 上限／未提交狀態為 `"unknown"`），但存在至少一項 `reasons` 缺口。
- **`unavailable`**：啟動在產生 session 前即失敗／取消且無任何 `session_results` 回執，或來源完全無法讀取且無歷史快照。
- **標準原因碼（`completeness.reasons`）**：
  - 重用 `session_reading.py:15-26`：`"bat_unreachable"`、`"session_not_found"`、`"transcript_truncated_by_size"`、`"archived_messages_omitted"`、`"parse_error"`、`"observation_stale"`。
  - Result／Changeset 原因碼：`"session_not_started_yet"`、`"start_outcome_uncertain"`、`"unloaded_history_session"`、`"worktree_unreachable"`、`"bat_empty_status_not_clean_proof"`、`"diff_exceeded_pipe_limit"`、`"commit_limit_exceeded"`、`"changeset_time_budget_exceeded"`、`"base_commit_not_ancestor"`、`"source_digest_conflict"`。
- **`completeness.coverage` 與 `last_successful_observation`**：回傳各區段完整度（`conversation`、`execution`、`changes`、`verification`、`delivery`）、視窗統計（`transcript_window`、`changes_window`）及 `last_successful_observation: {observed_at, collected_at, result_id, source_position, fixed_result_commit}`。
