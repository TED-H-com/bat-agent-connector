## 1. 看板 Work 檢視「成果」（Part A）

### 1.1 畫面位置與取代規則（Placement & Replacement）
- **位置與所有權**：由看板（`pm-kanban.js`）統一擁有 `<section data-work-section="attempt-result">`，排列於 `[data-work-section="start"]` 正下方、`[data-work-section="result"]`（若未隱藏）／`blocker`／`delivery`／`details` 正上方。該容器節點常駐 DOM，僅切換 `hidden` 屬性，面板元件不自行移除或重插 caller section。
- **能力閘門與替換**：當 workspace capability 宣告 `features.pm_workspaces.work_attempt_results`（`version: 1`）且最新 Attempt 擁有 session 並取得成果時，動態 Attempt Result 面板可見；此時 Inspector 內建靜態成果區塊（`[data-work-section="result"]`）自動隱藏。若無此 capability、最新 Attempt 無 session、切換至其他 Work 或成果讀取失敗撤回（401/403/404）時，Attempt Result 面板隱藏，原靜態成果區塊恢復顯示。

### 1.2 純讀取與資料庫邊界（Read-Only DB Access）
- **0 次 BAT IPC**：Part A 嚴格只呼叫 `GET /pm/workspaces/{ws}/work-attempts/{att}/result`，此為 Connector 本地資料庫之有界投影（0 次 BAT IPC、0 次 DB 寫入、不發出 `api_events`）。
- **禁止提前呼叫 `/changes` 與 `/diff`**：兩者皆會發起 Fleet/BAT IPC 呼叫；Part A 絕不自動觸發，完整檔案清單與 diff 檢視保留至 Part B 在使用者明確點擊時按需載入。

### 1.3 刷新與序號防抖規則（Refresh Rules）
- **事件驅動與票號保護**：當收到 `work.attempt.result_recorded` 或該 Attempt 相關事件時發起非同步讀取。每次請求遞增讀取序號票號（serial ticket）；回應返回時若票號或 Attempt ID 不符即視為遲到回應（late reply）並予以捨棄，避免跨 Attempt 或非預期順序覆蓋。
- **保留展開狀態**：各區塊（如歷史回合 `results` 清單、變更檔案清單、Details 原始資料）之 `<details>` 展開／收合狀態在資料重整與事件輪詢時完整保留，不因重新渲染而意外關閉。

### 1.4 狀態分離與誠實揭露（State Separation & Honest Data）
- **狀態分離**：模型自述（`self_reported`，如 `claimed_done`）、驗證（`verification`）、審閱（`review_decision`）、需求驗收（`acceptance`）、PR 與部署各自獨立呈現；代理自述「表示已完成」永遠標記為「未經驗證」，絕不視為驗證通過或需求已驗收。
- **未知誠實揭露**：BAT 未提供退出碼（`exit_code: "unknown"`）如實顯示「結束碼：BAT 不提供」；缺少或未列出的各項狀態皆顯示「未知」並於 Details 列出原始欄位值；BAT `git:status` 空陣列標記為「BAT 無法證明工作樹沒有未提交的修改」，絕不宣稱工作區為乾淨（clean）或未修改為 0。
- **退出碼與原因**：程序退出碼維持「未知（未由 BAT 提供）」；已知原因（如 `bat_unreachable`、`bat_empty_status_not_clean_proof`、`turn_boundary_not_collected`）在地化顯示，未識別之字串保留於 Details。

### 1.5 按需讀取目前變更與差異（Part B）
- **按需變更讀取（Read current changes）**：
  - 成果面版於能力具備時提供「Read current changes（讀取目前修改）」按鈕，僅在使用者明確點擊時呼叫 `GET /pm/workspaces/{ws}/work-attempts/{att}/changes`（0 次自動呼叫，不於掛載、事件刷新、切換或計時器觸發）。
  - 請求進行期間按鈕標記 `aria-disabled="true"`（不使用 `disabled` 屬性以保留焦點），目前變更區塊標記 `aria-busy="true"`，重複點擊與 Enter 鍵皆不發出額外請求。
  - 顯示內容包含最新 Head commit SHA（前 12 碼）、新鮮度（"Read from BAT just now"、"BAT could not be read. Showing the last recorded turn."、"BAT changes could not be read"）、變更統計摘要、原因條目、未提交修改說明（"BAT cannot prove the working tree has no uncommitted changes."、"BAT does not show diffs of uncommitted files."），以及完整變更檔案清單。
- **逐檔差異檢視（Show diff）**：
  - 檔案清單中每個提交皆提供「Show diff（顯示差異 · <sha12>）」折疊區塊（`<details>`），首次展開時呼叫 `GET /pm/workspaces/{ws}/work-attempts/{att}/diff?commit=<sha>&path=<path>`。
  - 關閉與再次展開皆由記憶體快取提供，不發出額外請求。
  - 差異以純文字（`<pre>`）呈現，具備 `role="region"` 與宣告路徑及 12 碼 commit SHA 之 `aria-label`；嚴格遵守 CSP，禁止渲染 HTML 或外來標記。
  - 支援有界限制提示（若 `truncated: true` 顯示「Showing the first 256 KiB of this diff.」）與不可用原因；502 / PM_DIFF_UNAVAILABLE 提供錯誤提示與重試按鈕，404 / PM_DIFF_NOT_FOUND 提示未找到且不提供無效重試。
- **過期偵測與再次讀取（Out of date & Read again）**：
  - 當收到信封變更的事件刷新時，保留已載入的目前變更與開啟之 diff，並於區塊頂端顯示「May be out of date（可能已過期）」標籤與「Read again（再次讀取）」按鈕。
  - 點擊「Read again」發起一次 `/changes` 讀取並清空已載入之 diff 快取與折疊狀態；讀取完成後過期標籤消失，「Read current changes」按鈕恢復。
- **焦點留在讀者停下的地方**：diff 的回應到達時，只在焦點仍停在該 diff 的 summary 上才移動焦點。從 summary 開始的讀取，成功或失敗都把焦點留在 summary。從該 diff 的 Try again 開始、而且再次失敗時，才把焦點移到新的 Try again，條件是當時焦點仍在該 summary。檔案路徑以屬性值比對，不把路徑拼進選擇器，因此路徑裡的引號或反斜線不會中斷繪製與焦點還原。成果讀取的 Try again 帶有 `data-work-result-retry="result"`，重新繪製時依這個屬性把焦點還原到同一顆按鈕。
- **操作導引與後續動作（後續部分）**：
  - 依 `next_allowed_actions` 接上 `session.send` 追加輸入、`github.pr.publish` 發布 PR 與品質審閱等動作入口保留於後續階段實作。
