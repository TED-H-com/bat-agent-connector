# Original maintenance execution completion

The original repair outcome (`published_for_review`, `merged`, or `deployed`)
remains an immutable delivery fact. Its capacity stays reserved until a separate
original coding-turn receipt establishes completion. Neither a send ACK, idle
metadata, interrupt ACK, missing session, nor a synthetic aborted turn qualifies.
This does not assert process death, fixed/released product status, or zero provider
billing.

`repository.continue` supplies a callback to the existing
`checkpoints.start_in_worktree` **first-send function**, after the original managed
start and before any input frame. Reconciliation of an already started send does
not invoke this callback. For an exact private repair child it records an immutable
origin: authenticated host configuration digest, original controller and registry
incarnation/creation identity, original SDK thread, fresh zero-turn replay cursor,
exact input digest, and original confined coding options. The existing PM observer
reducer remains read-only by default; coding evidence uses separate explicitly
named helpers that require the original confined start options. It does not gain
PM runtime isolation or turn execution authority.

The final unsent input frame checks the same SDK identity and an unchanged native
cursor through existing semaphore-safe guard reads. Unexpected input, confinement
drift, or a nonfresh session blocks the frame. Missing replay capability is recorded
as unavailable; it cannot later be upgraded from an idle snapshot. Old executions
without this original callback receipt can never acquire one retrospectively.
Their capacity remains held.

One server-only registered operation, `pm.maintenance.repair.runtime.observe`, has
scope `observe` and a stable `pm-repair-runtime:<parent-id>` key. Its target is the
original `{workspace_id, repair_id}`, params are empty, and its precondition fixes
`runtime_origin_digest`. Public callers cannot create its private relation. The
existing repair reconciler admits this reader; the existing OperationService runs
it. No separate queue, runtime, model request, maintenance reservation or write is
introduced. It starts reading while delivery is still pending, preserving replay
before BAT's native retention expires. Current original-controller credentials and
current access to **every original source** are required on each read and local
receipt. Pause, close, changed policy, or the investment deadline do not prohibit
read-only recovery. Credential loss retains the same pending operation.

Pages retain exact contiguous native events, epoch and cursor in append-only rows
and local OperationService receipts. A request is bounded to 15 seconds; stored
coverage is bounded to 256 pages, 4096 events and 2 MiB. Snapshot replacement,
epoch/sequence gaps, later input, changed session/options, incomplete messages,
multiple terminals and aborted/error terminals do not release capacity. The
original one input must match its saved digest and its original native completed
turn must identify the same SDK thread. Pages and original receipt recovery are
idempotent; this reader has no input, interrupt or start path.

Before release, the original repository child, original publication and policy
ceiling result must be terminal, with no other active or uncertain derived effect.
The saved quality assessment must independently contain the adopted passing
verification for the exact published candidate/tree. A bounded read of the actual
original managed Git carrier must still show that clean candidate/tree. A final
native replay and metadata check rejects later input, changed SDK, additional
turns or a still-streaming runtime. These observations supplement the native
completion event; they never substitute for it.

`runtime.proof(ops, principal, parent)` returns an immutable
`pm_repair_runtime_completion_v1` document and digest containing original execution
and observation operation IDs, session/incarnation/SDK/native turn identities,
original/completion cursors, event digest, exact verification/quality/publication
references and candidate/tree. Proof insertion, local completion receipt and
`pm_maintenance_repairs.finished_at` are one journal transaction. The document says
`runtime_status: original_turn_completed`, `process_death_proven: false`,
`repair_fixed: false`, `release_publication: not_inferred`. The parent operation's
old result is not rewritten. `get_repair` projects the new proof separately as
`runtime_completion`, with `runtime_observer`, `runtime_origin_status` and current
`capacity_held`.

Shared read/operation/event surfaces retain the complete original source barrier.
Historical proof reads remain possible after source runtime disappearance when
source access remains authorized. Withdrawal of any original package, finding,
quality/verifier or delivery source hides the whole record. Workload and report
consumers must select this exact immutable proof and its original execution; a
matching session string or generic succeeded operation is insufficient.

## Current input identity and workload

Completion additionally requires `inputState` from authenticated native metadata:
`{schema:"bat_input_state_v1",epoch,received,pending}`. The epoch is a new runtime
nonce; `received` counts cumulative ordinary input entries, including queued and
preparation phases; `pending` retains entries until their original processing has
settled. The original pre-send receipt fixes that epoch at zero received/pending.
The completed native replay and final metadata must retain the same epoch with
one received input and zero pending. SDK `numTurns` is not a user-input count.
A host without this evidence cannot release the repair reservation or gain it
retroactively from a later read.

A later workload capture excludes only the original maintenance execution,
unchanged fixed work-item version/content, and same registered session when its
fresh authenticated inventory preserves that exact completed input identity.
Source references retain the original immutable completion receipt and its full
policy/package/verification/publication source chain. New SDKs, second or queued
inputs, foreign/manual sessions, stale/incomplete discovery, pending questions,
active work, and original source withdrawal keep their existing blockers. This
creates no Task, edits no work state, makes no Maintain transition, and proves
neither process death nor a fixed Issue or published release.


The proven early-SDK path is a fresh Rust Codex coding session. Its existing
adapter trims Unicode White_Space before native turn input/echo; the immutable
origin retains both the raw owner-request digest and explicitly labelled native
text digest. Claude's exact-text normalization is separate. Legacy Claude hosts
that expose no SDK identity before their first input remain unavailable for this
completion contract; an idle SDK discovered afterward cannot adopt an old origin.
