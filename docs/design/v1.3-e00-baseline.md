### 7.3 最小共用 response（提案）

人／agent 都應取得：`work_id`（既有 `work_item_id`）、`attempt_id`、`operation_id`（含 parent 與必要 child refs）、`state` 與來源／觀測時間、`next_allowed_actions`（每項含 allowed／blocked_reason）、`dashboard_deep_link`、`completeness`／coverage／cursor。未建立 Attempt 或沒有資料就明確 absent/unknown，不造假 ID 或零值。外部 observed Result 可以沒有 Work/Attempt，回「未歸類」與允許的 link/derive。

Operation 的 `succeeded` 只表示該操作完成；start succeeded 回 `runtime_started/input_accepted`，不寫 `work_accepted`。Result 列 raw/self-reported、verification、requirement acceptance、PR/merge、release/deploy 各自 status/ref。unknown command 的 next allowed action 是 read/reconcile／提供 evidence，不是 start-again。

deep link 在中央以受限識別碼與相對 Dashboard route 產生；不接受 provider 給任意帶 token URL。舊 operation/session deep links 繼續可用。scope/source 撤回時，API read、MCP wait、events、UI row/count/inspector 一起重核；延遲 response 必須有 generation／request ticket，不能復活已撤回內容。現有 AHP 全 receipt withdrawal 是可沿用範例，`tests/test_pm_ahp_observations.py:236`（測試原碼）。

| maintenance | release baseline verified → idle coverage fresh＋policy adopted → Maintain → finding → own repair → verified／PR → Maintenance Review。 | Paused/Closed 阻擋新 repair；sent-effect 繼續查回，不喚醒舊佇列或 archive repo。 |

Golden 固定 Git SHA／digests 用 `desktop/tests/demo/project.ts:12`、`desktop/tests/demo/project.ts:15` 的合成 helper；fixture 標記 synthetic。真正 acceptance 改用暫存測試 repository 產生的真 commit／tree／verification log／測試 PR receipts，不能讓 runtime 直接回合成 SHA 冒充成果。
