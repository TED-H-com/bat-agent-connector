# Dedicated BAT PM analysis

`pm.run.bat.analyze` is a registered central operation for one frozen Idea or
Planning discussion. It accepts the same discussion target, purpose, optional
model, context bound, timeout and expected thread version as native analysis.
Prepare the workspace's configured PM worktree first. Its original repository,
host and BAT workspace selection are reused; a path or workspace label cannot
select another host or claim an existing human session.

The operation reserves the existing PM writer generation and workspace PM
controller. A trusted internal context reuses the ordinary durable standalone
start executor, including resource policy, the original PM carrier creation ID,
incarnation, confinement, final-frame guards and sent-effect reconciliation.
Public `session.start` cannot choose this internal profile. The runtime receives
only frozen context and runs in its private empty directory. The Connector
continues to own PM documents, discussion imports and scope decisions.

The logical carrier is the already-proven PM clone/worktree, not a new worktree
under the human workspace. A private PM-only start binding freezes its original
creation operation, configuration, marker, clone/worktree paths, branch and exact
append-only Git tip. The original BAT workspace ID and folder remain separately
bound. Every new BAT frame checks the current workspace metadata and the original
host carrier evidence; arbitrary same-path folders or Git descendants are refused.
The start engine records only a read/bind receipt for that existing carrier and
never calls `worktree:create` for this path. Ordinary session starts are unchanged.
The native process still uses its isolated empty cwd, not the logical PM checkout.

After a completed original run and confirmed process death, a new explicit
analysis operation may use the next writer generation, same durable discussion
and PM files, and a new own BAT session/native thread. Service restart does not
erase the prior context or release unknown writers. The bounded discussion
context reports omitted content; it does not claim every accepted document was
loaded. Adapter selection across tools and native coding are separate contracts.

After the immutable import, a local idempotent registry retirement releases only
that original runtime incarnation from the host session cap. It uses the saved
dedicated-process death proof and never sends a stop or another input. A crash
between import and retirement recovers the same local receipt. The existing PM
worktree and historical session row remain intact. Both successor reservation
and final transport checks require the original completed run, death proof,
controller, incarnation, same carrier creation/configuration and current writer.
A retired label alone, an unknown exit, a foreign session or a reused path grants
no sharing authority. Sequential completed turns work with a host cap of one.
Cancellation after successful import also permits this proven local retirement;
current original source and identity checks remain mandatory.

The BAT prerequisite is the additive `codex-pm-linux-v1` contract on top of
audited upstream `b7419892fbc9946799b64cca24c2ec8c7fa15c42`, with pinned Codex
`0.160.0` / `a956835d020762cb2b570053af06f643a11c0ecc`. This contract requires a
dedicated isolated process, no inherited environment access, no MCP servers or
skills, read-only filesystem options, a fresh thread and a single native input.
The capability descriptor is configuration eligibility; actual attestation,
authentication and model execution remain separate per-run evidence. The
ordinary BAT profile's external-tool limitation remains unchanged.

The owner fork's [server package change](https://github.com/TED-H-com/better-agent-terminal/pull/3)
provides a fixed Linux x86_64 candidate and a
[deployment guide](https://github.com/TED-H-com/better-agent-terminal/blob/737f6fb256716e190f34795dc27d6341ba0bc345/docs/pm-server-candidate.md).
Its manifest and smoke receipt identify the exact source and payload hashes.
The ordinary bundled Codex is separate from the required PM Codex 0.160.0;
operators configure that PM executable explicitly. Package tests prove bounded
offline startup, authentication and restart behavior, not model execution or an
installation on an owner's host.

Start and send have distinct durable receipts. The send requires an authenticated
fresh `claude:sync-session` cursor, original runtime/context IDs and a fixed
`clientMessageId`. That cursor, prompt digest and transport fence are persisted
before writing. A missing ACK never creates another process or input; recovery
reads the original native receipt and replay. Cancellation, source withdrawal,
membership changes and lifecycle stops block a new frame. Original read-back
does not select a newer context or adopt another native thread.

One synchronous PM start guard shares completed historical source decisions
between its profile and carrier checks. Both original controller checks still
run, including current writer, membership, cancellation, deadline and binding
checks. This read-only snapshot ends before any await or write; each subsequent
guard and final transport frame starts fresh. The ordinary session-start guard
and its resource, policy, registry and cleanup checks remain outside this scope.
Each PM frame's current-writer and requester checks likewise share only their
completed historical source decisions within that synchronous fragment. Both
checks run on every invocation, including after native reads; no writer grant,
membership, cancellation, deadline or binding decision is cached.

Assistant import requires contiguous original replay, exactly one original
input and completed turn, matching native terminal JSON digest/output digest,
and confirmed death of the original dedicated process. A native message ID in
BAT's replay and the underlying app-server item ID are distinct; both remain in
their original evidence. ACK, idle state and synthetic abort do not satisfy this
contract. For ordinary analysis, the existing assistant provenance import is
the sole discussion write path; analysis never adopts a plan or launches
engineering work.

The same executor also serves `pm.conversation.propose` and
`pm.follow_up.analyze` when their original request explicitly selects
`adapter: bat-pm-linux-v1`. Trusted callbacks freeze each action's context and
import only its fixed proposal/assessment destination; the ordinary discussion
importers refuse those destinations. Workspace `structured_analysis.version: 1`
advertises per-action descriptors. Native remains the absent-adapter default,
and the original key cannot change adapters. This adds no automatic fallback,
second start engine, caller-supplied proof or general runtime selection policy.

Structured import recomputes the original replay, runtime completion and
process-death proof inside its journal transaction. Local receipt failure keeps
the original operation recoverable; a committed import is read before admitting
new work or retiring its original runtime. Public provenance has an explicit
nested schema, including original process identity, exit/observation and source
digests. Raw diagnostic fields remain private, including on ordinary run reads.
The complete immutable runtime observations are preserved for reconciliation.

Failed preflight has a separate abort-only proof: the original persisted failed
record can positively prove no launch, or the original process identity can
prove death even before thread/attestation completion. Preparing records,
missing receipts and unknown process identity retain the writer. An abort-only
proof never authorizes sending or importing an assistant answer.

`claude:get-pm-runtime` is read-only. It preserves original binary/source and
process identities, native completion and actual exit evidence separately from
Connector's local native-CLI journal. Observation records are immutable and
bounded; no new schema migration number is allocated. Derived session reads
retain current original workspace access.

Offline integration tests use MockBat and the actual central operation service,
session-start engine and transport fences. They cover completed import, original
lost-ACK recovery, missing exit, replay gaps, unproven tools, final-frame
membership withdrawal and abort-only preflight receipts. These checks do not
claim a BAT installation, live model turn or hardware acceptance.
