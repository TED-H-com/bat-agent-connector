## 本次產品成果

讓使用者不離開Dashboard就能：**說需求／討論 → 形成必要計畫 → 明確開始自有工作 → 看真實stream/diff/驗證 → 再下一句修改 → PR/交付 → PM回填。**

同時要做到：不同CLI的既有或新建session結果回到同一工作模型；Hermes/Grokbot等agent經API/MCP做同樣操作，Dashboard立即看見相同Work/Attempt/Result。

不要將本次改版縮成畫面改色、增加說明文字、列出工具名、把使用者送去外部agent，或只有observer沒有自有執行。

## 明確保留

- Python Connector、既有TaskDaemon/OperationService/journal、BAT engine與GitHub交付原語。
- Tauri＋共用Web frontend，以及現有六PM管理視圖、Board、Discussions。
- server/workspace本地管理邊界，多client共享服務資料；同repo跨server不自動合併。
- PM專屬worktree、docs/pm、Idea、Planning、SDD、Sprint、Release、Maintain、Paused/Closed與決策歷史。
- manual/foreign/unknown session不接管、不送字、不resume、不interrupt、不清理。link到Work不產生控制權。
- 原生coding輸出格式；以adapter讀原生events/transcript/Git，不要求使用者修改所有prompt。

## 必須校正

1. **Send必須符合使用者理解。**討論的主要傳送動作要真正讓PM回覆；只保存是「只存筆記」。Idea回應不強制產生提案，更不開發。
2. **採用並開始必須可用。**組合現有採用、工作包和start/handoff，保存每步結果；不用人手寫`pm.work_package.create`或找operation IDs。
3. **新工作有自己的執行空間。**利用已確認的profile與來源，自動建立自有worktree/session，直接顯示在原Work頁。
4. **第二句不丟失。**追加自己的工作，busy預設排下一輪，不意外steer或中斷；結果回同頁。
5. **外部工作只讀但有用。**可看成果、連需求、整理PM、從固定成果另開自己的工作；不得認領他人的session。
6. **同一API/MCP契約。**外部agent不需要點UI，不共享owner管理憑證；跨controller送Work inbox或derive，不冒用身分。
7. **結果必須可信。**原始來源、parser/adapter版本、coverage、Work/Attempt、commit、測試、PR與部署分清；結束輸出不等於驗收。
