## 跨 CLI 用量：下一階段要做的事

這項列入 **W30／P2 規劃**，沒有實作 collector、掃描私人對話或變更模型政策。
應涵蓋每個被支援的 CLI，但依實際版本的 adapter 與資料能力逐一驗證，不能先宣稱全支援。

| 要做到 | 為什麼有用 |
| --- | --- |
| 各機器本機增量聚合、checkpoint、去重與累計重設處理 | 避免每次重掃巨量紀錄；原始對話不送進模型或公開網站 |
| 回報 CLI／版本／模型／來源分類及資料涵蓋 | 子代理、獨立 exec 與主對話不混算；缺欄位維持未知，不當零 |
| 分開 input、cached input、output、reasoning 的包含關係 | 不重複相加；無 cache-write 證據時不拿未快取輸入代替 |
| 將用量接回工作、合格交付、返工與等待原因 | 找出重複派工、冗長脈絡或無效重試；總 token 排名不等於成本排名 |
| 先建議、再依採用政策調整新的自有工作 | 評估批次查詢、少輪詢、階段交接、適當模型／effort；同時追蹤品質是否下降 |

圖表應幫使用者決定「哪種工作值得改，改完是否更有效」，而不只是每天顯示大數字。
API 估价、實際帳單、訂閱配額與 token 流量分開標示；間隔超過五分鐘也不能直接證明快取過期。
不接管人工 session、不改既有執行中的模型，不以固定四分鐘等待規則取代實測。
